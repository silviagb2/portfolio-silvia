CASE STUDY

Building a scalable foundation
for growth

This project started with a simple observation: the gap between design and production was too big to patch. So I proposed we fix it properly — with a Design System.

How I am evolving a simple UI library into a robust Design System to increase consistency, improve collaboration, and support the future growth of the Fine Dining Lovers platform.

THE EXISTING LIBRARY

Auditing the foundation

Before building anything new, I needed to understand exactly what we were working with. Using AI-assisted tooling, I ran a systematic audit of the live platform — extracting and analyzing every design decision embedded in production code.

The picture was clear: the platform had grown faster than its design foundations. I found over 45 hardcoded color values with no token system connecting them, a typography scale applied inconsistently across the codebase, and 33 different border-radius values with no shared logic.

It wasn't that the decisions were wrong. They'd just never been made intentionally, as a system. That audit became the brief for everything that followed.

THE PROBLEM

When speed
leaves gaps

The FDL platform was built under tight deadlines. Design and development moved fast — necessarily so — but that pace left little room to build things together. The result was a UI library that had grown organically rather than intentionally, and by the time the platform stabilised, the cracks were showing.

Inconsistencies

Different teams were creating slightly different versions of the same components. Without a shared source of truth, the same button could look three different ways depending on who built it.

Inefficiency

Developers had to guess at design specs or rebuild components from scratch. Every handoff took longer than it should.

Growing out of scale

A strategic decision to update our responsive breakpoints forced manual adjustments across the entire platform — something that should have taken days took weeks.

We realized we didn't just need a new library; we needed a new way of working. We needed a true Design System.

THE GOAL

A system built
to last

Our goal wasn't just to clean things up. It was to build something that the whole team — designers and developers — could actually rely on and contribute to. Three objectives guided the work:

01

Consistency across the platform

One set of intentional decisions — available to everyone. The right color, the right spacing, every time.

02

Faster collaboration

Designers and developers speaking the same language from the start — not interpreting each other's work at the end.

03

A foundation that scales

Responsive breakpoints, new features, new teams — the system had to be able to absorb all of it without breaking.

OUR APPROACH

Building the foundations

I started by focusing on the core foundations of the design language: architecture, typography, color, and spacing.

Architecture first

Before touching any component, I defined how the system would be structured. A clear architecture meant every designer could know exactly where to find what they needed — and where to put anything new. It also meant the system could grow without becoming another source of chaos.

Revamping typography

The existing type system had grown without a clear scale — too many sizes, applied inconsistently across the platform. And what reached production often didn't match the designs: sizes were interpreted freely by development, leaving some modules significantly larger than intended.

The responsive logic was equally fragmented. There was no shared system defining how sizes should adapt across breakpoints — each module handled it differently, making the platform feel inconsistent.

I rebuilt it from scratch using Figma's Modes: one clean, intentional scale with a defined relationship across breakpoints. Define it once, and it works consistently everywhere.

Creating a smart color system

The audit made one thing clear: the platform had almost no intentional color tokens of its own. There were only a handful of custom variables — and dozens of hardcoded hex values applied directly in the CSS with no connection to any system.

I rebuilt the palette from scratch. Simplified, named intentionally, and structured around semantic tokens that describe a color's purpose rather than its value — color-background-primary instead of a hardcoded hex. This makes the system easier to maintain, easier to hand off to development, and ready for future features like Dark Mode.

Establishing spacing & shape

The 8-point rule was there in theory — but in practice, spacing values were chosen freely. Without a defined scale, every module made its own decisions. And just like with typography, there was no shared logic for how spacing should adapt across breakpoints: a gap that worked at desktop could shrink — or grow — to a completely unrelated value at mobile, depending on who had built it.

The same was true for border-radius: 33 different values across the platform, with no logic connecting them.

I created a token-based scale for both — intentional values that define not just the sizes, but how they respond across breakpoints. Consistent by design, not by chance.

IMPACT & NEXT STEPS

An ongoing foundation

This is a project in progress — the foundations are in place, and the team is now building the first components on top of them. But the impact is already visible.

Impact so far

When a breakpoint change came in, the update was fast. When the client requested typography changes across the platform, we made them in one place and they propagated everywhere. Tasks that would have previously meant hunting down every instance across the codebase now take minutes.

Developers have already started implementing the new tokens in production. The system is being used — and it's working.

What's next

Our work on the Design System continues, with a clear roadmap:

01

Build out the first set of core components — buttons, inputs, and cards — using the new tokens.

02

Propose Storybook to create a live, interactive library that keeps design and development always in sync.

03

Establish a governance model to define how the system grows and stays consistent over time.
